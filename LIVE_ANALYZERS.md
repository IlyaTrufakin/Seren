# Seren: основное приложение и независимый monitor1654

Реализовано 2026-10-11. Установлена задача Windows **SerenSystem** для текущего пользователя. Она запускает систему при входе пользователя после загрузки ОС. Графические окна требуют входа в Windows; до входа они не работают.

## Первый запуск

1. Закройте прежнее окно основного приложения, если оно открыто.
2. Запустите `run_system.bat`. Откроются основное приложение и независимый анализатор monitor1654. Основное приложение, как прежде, автоматически подключается к настроенному ПЛК.
3. Проверьте карточку «Дополнения к базе API»: связь с анализатором и связь анализатора с Telegram отображаются отдельно. Анализатор сначала восстанавливает последние 30 минут контекста; до окончания восстановления ничего не повышает.

Приложения при разработке не запускались с реальным ПЛК. Проверен реальный публичный Telegram и передача в изолированный локальный приёмник.

`run_monitor1654.bat` запускает только анализатор. Он не подключается к ПЛК или API. Для автоматического восстановления после падения запускайте систему через `run_system.bat` либо вход в Windows.

## Итог тревоги

Итог — максимальная степень среди базы API и действующих дополнений анализаторов, а не арифметическая сумма. Все активные типы объединяются. При одинаковой степени прежний приоритет звука: ракета, КАБ, дрон, неопознанная. Звуковые профили, расписание, общий таймер звука и обмен с ПЛК сохраняются.

Есть четыре состояния: нет, низкая, высокая, критическая. Внутренние коды протокола 0/1/2/4 сохраняются для совместимости; районные коды 3/5 в анализаторе сводятся к высокой/критической степени.

API-условия основного конфигуратора определяют только базу. Внешний анализатор сообщает уже рассчитанную степень; основной модуль использует соответствующий звуковой профиль даже если API-условие этого профиля отключено. Общий выключатель обработки, тумблер ПЛК и тихий час продолжают действовать.

Отмена или пауза monitor1654 снимает только его собственное дополнение. Пропадание анализатора дольше 15 секунд снимает его дополнения, сохраняя API. Потеря связи анализатора с Telegram отображается отдельно: уже подтверждённая угроза сохраняется до своего срока действия, новые сообщения отсутствуют. Отсутствие необязательного анализатора само по себе не включает звук потери API.

## Анализатор и настройка

В окне: текущая степень и типы, причина, список последних 300 сообщений, реакция выбранного сообщения, графики по каждому типу и маркер выбранного сообщения. Колесо масштабирует график; щелчок выбирает сообщение. График хранит до суток текущего сеанса, начальное окно — до 6 часов; при запуске восстанавливается контекст последних 30 минут.

«Пауза / настройка» прекращает передачу повышения; главное приложение продолжает API. «Словари и правила» автоматически включает паузу. После сохранения профиль перечитывается; нажмите «Продолжить» для восстановления контекста и возврата в работу.

«Архив / критерии» открывает существующий архивный отладчик с профилем monitor1654. Архивный отладчик ничего не отправляет основному приложению. Для изменения профиля во время эксплуатации сначала поставьте живой анализатор на паузу, внесите коррекции и проверьте критерии на архиве, затем нажмите «Перечитать профиль» и «Продолжить». Настройки и размеченные критерии остаются в `profiles/monitor1654`; словари не копируются в основной модуль. В живом и архивном режимах используется один алгоритм.

## Журналы и протокол

- `logs/analyzer_monitor1654_YYYY-MM-DD.jsonl`: входящие сообщения, реакции, изменения уровней, ошибки Telegram, паузы, перечитывание профиля и связь с основным приложением.
- `logs/external_receiver_YYYY-MM-DD.jsonl`: принятые состояния.
- `logs/main_api_debug_YYYY-MM-DD.jsonl`: API и итоговое решение, включая состояния анализаторов.
- `logs/supervisor_YYYY-MM-DD.jsonl`: запуски, падения и перезапуски. `*_process.log` содержит вывод процесса и необработанные исключения.

HTTP `POST http://127.0.0.1:8765/v1/state`, снимок каждые 2 секунды. Приёмник слушает только localhost. Общий случайный ключ хранится в `runtime/analyzer.key`, не попадает в Git. Снимок содержит версию 1, канал, идентификатор сеанса, последовательность, время, уровни и фиксированные сроки каждого типа, причину и исходные сообщения, связь Telegram и флаг паузы. Старые, перепутанные по порядку и некорректные снимки отклоняются; периодическая передача не продлевает TTL угрозы.

`config_analyzers.json` задаёт порт, срок отсутствия связи, интервал отправки и до трёх разрешённых каналов. Сейчас подключён только monitor1654. Для другого компьютера сетевой протокол намеренно не открыт: текущая поставка рассчитана на localhost.

## Автозапуск и восстановление

Задача планировщика запускает `pythonw.exe -m src.system_supervisor`. Супервизор запускает оба независимых процесса, восстанавливает их после ненулевого кода завершения с задержкой 3–60 секунд и перезапускает зависшее окно: 45 секунд без GUI heartbeat после 90 секунд начального допуска. Сам супервизор при падении перезапускается планировщиком через минуту.

Обычное закрытие окна считается намеренным отключением; супервизор не открывает его заново. Повторный вход в Windows запускает оба приложения. Для возврата закрытого анализатора в текущем сеансе используйте `run_monitor1654.bat`; для настройки предпочтительнее пауза, сохраняющая наблюдение супервизором.

На другом ПК после установки окружения выполните `install_autostart.ps1` от своего пользователя. Скрипт не запускает приложения. При недоступности планировщика создаётся ярлык текущего пользователя в «Автозагрузке»: восстановление дочерних приложений сохраняется, но сам супервизор восстанавливается только при следующем входе. Удаление автозапуска: `uninstall_autostart.ps1`; текущие процессы при этом не закрываются.

## Исправление супервизора 2026-10-11

В Windows виртуальное окружение запускает Python через промежуточный процесс: PID, возвращённый Popen, отличается от PID окна. Первоначальная проверка ошибочно считала оба приложения зависшими через 90 секунд. Исправлено сопоставление по уникальному идентификатору запуска и PID процесса запуска; добавлен регрессионный тест. При настоящем зависании завершается всё дерево этого приложения, чтобы не оставлять работающий дочерний Python. Работающий супервизор обновлён с передачей уже запущенных окон, без перезапуска основного приложения/ПЛК.

## Потеря базового API — 2026-10-12

Основной модуль после ошибки API сразу исключает его прежние данные из расчёта. Действующие снимки подключённых анализаторов независимо задают итоговые типы, уровень и звуковой профиль; тревожный звук приоритетнее звука потери API. Если API ещё ни разу не ответил или его данные устарели, расчёт по анализаторам также действует. При успешном восстановлении API возвращается обычная композиция максимум базы и анализаторов. Пауза, отключение или истечение срока снимка анализатора не считаются подтверждением отсутствия угроз: при недоступном API звук потери связи остаётся только если нет ни одного действующего подключённого анализатора с доступным Telegram. Если такой анализатор передаёт нулевые уровни, используется обычный профиль «Нет тревоги» и показывается «Нет активных угроз по анализаторам». 184 теста прошли, включая API-outage, устаревшую/незагруженную базу, приоритет тревожного звука и восстановление API. Radar остаётся отключён от основного модуля. Код требует перезапуска основного окна; реальный ПЛК для проверки не запускался.

## Доступен анализатор, уровень нулевой — 2026-10-12

Отсутствие тревоги не означает отсутствие источника. При API HTTP 429 и monitor1654 connected/source_online=true, paused=false приложение работает по анализатору, в том числе при level=0. Сигнал общей потери связи не включается, бит общей потери связи снят, недоступность API отдельно видна в карточке API. Если анализатор на паузе, отключён или его Telegram недоступен и API тоже недоступен, общий звук потери связи остаётся. Тревожные уровни имеют прежний приоритет над этим звуком. 186 тестов прошли. Рабочий процесс должен загрузить новое исправление после перезапуска основного окна; ПЛК при проверках не запускался.

## Приостановка запросов — 2026-10-12

В карточке API основного окна добавлена кнопка «Приостановить запросы API» / «Возобновить запросы API». Приостанавливает все HTTP-запросы AlarmMap, включая ракеты, баллистику и справочники; запрос, уже переданный серверу, физически отозвать нельзя, но его поздний ответ не принимается. При паузе база API исключена, а подключённые анализаторы продолжают задавать итог. Пауза не сохраняется после закрытия приложения, но сохраняется при редактировании конфигуратора в текущем сеансе. Интервал API задан в config_main.json и показан в конфигураторе; прежняя задержка между циклами сохранена.

В обоих анализаторах добавлена отдельная кнопка «Приостановить чтение Telegram» / «Возобновить чтение Telegram». Останавливает получение новых сообщений; действующие угрозы сохраняются до первоначального TTL. Передача имеющегося состояния monitor1654 и графики продолжаются, но источник Telegram отмечается как приостановленный/недоступный. После возобновления восстанавливается контекст, пропущенный во время паузы. Это отличается от «Пауза / настройка», которая снимает дополнения анализатора. Radar по-прежнему ничего не отправляет основному модулю.

Telegram опрашивается примерно раз в 5 секунд, с дополнительной задержкой загрузки. Графики обновляются примерно раз в секунду. 191 тест прошёл, включая запрет запросов, отказ от позднего ответа API, независимость анализаторов и паузу Telegram. Для появления кнопок нужно перезапустить соответствующие окна; основной модуль и реальный ПЛК для проверки не запускались.
