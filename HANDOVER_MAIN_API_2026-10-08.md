# Основной модуль — 2026-10-08

Пользователь отложил анализаторы и запросил поэтапную эксплуатацию основного приложения только по API. Сетевой сервер анализаторов пока не реализовывать. База API + будущие дополнительные угрозы остаётся концепцией системы.

Основное окно src/app.py использует MainSystemConfig (src/main_config.py), ApiMainEvaluator (src/main_evaluator.py) и MainConfigDialog (src/main_config_dialog.py). config_main.json — источник истины для основного модуля; словари и Telegram-параметры туда не входят. Общий архивный ThreatEvaluator и профили анализаторов сохранены отдельно.

Новый SoundProfile.total_duration_s: 0 без ограничения, целые секунды до 86400. Таймер реализован в API-модуле по monotonic, общий период с паузами, сброс при смене кода. Окончание передаёт beep_count 0 при сохранённом коде и битах тревоги. Формат MW2..MW6 не меняется. Сохранение настроек сохраняет актуальное API-состояние и объект таймера, если источник и территория прежние.

MainAlarmRule.level_code позволяет выводить 1, 2/3 и 4/5 по API-параметрам. Для API match_rows использует это явное соответствие; существующие Telegram-правила продолжают вычислять степень по приближению.

Проверено 112 тестов. Реальные API/Modbus при проверках подменены. Физический ПЛК не подключался, программа в нём не обновлялась. Подробности эксплуатации и ограничений: MAIN_API_STAGE.md. Старые удаления файлов и пользовательские изменения сохранять. Коммиты не создавались.


Последующее уточнение пользователя: в основном модуле только четыре категории (нет/низкая/высокая/критическая). MainConfigDialog теперь показывает галочки входных уровней: air 1–3, КАБ/дрон/FPV 1–2, без JSON. Выходной код фиксирован по степени (0/1/2/4 для совместимости с ПЛК), прежние 3/5 при загрузке main-конфигурации нормализуются к 2/4. Словари и архивный алгоритм остаются вне основного модуля.


Добавлены general_api_levels для бомбовых правил: по прямому ответу пользователя общий уровень И уровень КАБ должны совпасть одновременно. В GUI оба набора галочек; текущая/старая конфигурация по умолчанию разрешает общие 1–3, запись air обязательна. ApiMainEvaluator._rule_matches проверяет общее условие только для КАБ.
Добавлен MainAPIDebugLogger: каждый API-опрос с сырым JSON и рассчитанным состоянием, отдельные записи изменения решения и короткие записи в системном журнале GUI. logs/main_api_debug_YYYY-MM-DD.jsonl, Kyiv timezone, ключи не пишутся. 119 тестов прошли; текущий config_main.json обновлён без изменения звуков.


Новое уточнение: дроновый тип только по явной записи дрона/FPV. Неуточнённый air/1–2 — общая воздушная тревога (внутренний тип unknown), air/3 без уточнения пока сохраняет прежнюю ракетную классификацию. Настроенные общие уровни перенесены из дроновых в отдельные общие правила; звуковой рисунок и ограничение времени сохранены при переносе. Нижняя карточка показывает только действительные уточнения API; при отсутствии отдельного типа и его уровня пишет «не указан API».


Актуальное правило по последнему указанию пользователя: любой air без явного уточнения типа (уровни 1, 2, 3) классифицируется как ракетный. Явные КАБ/дроны/FPV сохраняют приоритет. Неуточнённые общие уровни перенесены в ракетные правила соответствующей степени; существующие ракетные звуковые профили сохранены. В нижней API-карточке по-прежнему «не указан API», поскольку классификация приложения не является уточнением источника. main air_classification_version=3. Проверка: 121 тест пройден.


В дроновых правилах конфигуратора восстановлен выбор общего уровня 1/2/3. Теперь дрон и FPV работают как КАБ: общий уровень И выбранный уровень уточняющей угрозы должны совпасть. Общее условие сохраняется отдельно, поэтому air без уточнения остаётся ракетным. При переносе разрешены общие 1–3, затем выбор можно сузить.
