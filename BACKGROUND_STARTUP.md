# Работа Seren без входа пользователя Windows

Два режима разделены: фоновые рабочие процессы и графические интерфейсы. Фон получает AlarmMap API, управляет ПЛК и запускает monitor1654/radar_kharkov без Tk-окон. После входа пользователя привычные окна показывают состояние фоновых процессов и передают команды; они не создают второе соединение с ПЛК/API. Закрытие окна не останавливает фон.

## Установка

`install_background_admin.ps1` запускать из PowerShell с правами администратора. Нужны права Windows для задач под служебной учётной записью. Установщик предоставляет NETWORK SERVICE чтение кода, окружения Python, профилей, конфигураций и только используемого API-ключа. Запись разрешена только в logs/runtime. Пароль пользователя не хранится.

Установщик сначала запускает проверочную задачу в НЕИНТЕРАКТИВНОЙ служебной учётной записи: читает конфигурацию/ключ и проверяет HTTPS Telegram. ПЛК в этой проверке не подключается. Только после успеха включается config_background.json и регистрируется задача SerenBackground.

Задача SerenBackground запускается через 20 секунд после старта ОС под NETWORK SERVICE, независимо от входа пользователя. Запускает `pythonw.exe -m src.system_supervisor --background`, который отдельно запускает main/monitor1654/radar_kharkov через background_runner. Каждый упавший процесс восстанавливается через 3–60 секунд, сам супервизор — планировщиком через минуту. Если при запуске интернет/ПЛК ещё недоступны, обычные попытки восстановления связи продолжаются.

Производственный фон установщик НЕ запускает в текущем сеансе, чтобы не пересекаться со старыми работающими окнами. Он начинает работу при следующей загрузке ОС. Старые приложения нужно закрыть перед перезагрузкой, сохранив настройки. После неё вход в Windows для самой работы не нужен.

## Работа с окнами после входа

Существующий автозапуск SerenSystem открывает окна интерфейсов после входа. Можно использовать прежние run.bat/run_system.bat/run_monitor1654.bat/run_radar_kharkov.bat. При enabled=true они не управляют ПЛК и не опрашивают онлайн-источники самостоятельно. В интерфейсах работают профиль/графики, пауза анализа/чтения Telegram, пауза API, включение/выключение соединения ПЛК и квитирование. Настройки сохраняются в прежние файлы; фон автоматически перечитывает изменённые конфигурации и профили. Открытие окна, когда фон недоступен, показывает отсутствие его состояния вместо запуска дублирующего управления.

Команды подписаны локальным ключом runtime/analyzer.key; очередь файлов в runtime/commands. Состояния background_main.json/background_monitor1654.json/background_radar_kharkov.json обновляются фоном; данные старше 15 секунд не считаются текущими. Журнал фонового супервизора: logs/background_supervisor_YYYY-MM-DD.jsonl, фонового основного модуля: logs/background_main_YYYY-MM-DD.jsonl. Журналы API/анализаторов сохранены.

## Проверка после отключения электричества

ПК должен сам включаться после возврата питания: в BIOS/UEFI включить Restore on AC Power Loss / AC Back / Power On (название зависит от платы). Windows-задача не может включить полностью обесточенный ПК. Ключи и файлы Python/профилей должны физически храниться на локальном диске, не только в облаке Dropbox.

Проверка реального сценария: загрузить ПК без входа, подождать доступности сети, затем проверить работу ПЛК и после входа журналы фонового запуска. Проверка служебной учётной записи подтверждает доступность сети/файлов без GUI, но не заменяет настоящий перезапуск ОС и проверку физического ПЛК. Разработка и автоматические тесты реальный ПЛК не включают.

Обычное закрытие GUI не прекращает фон. Для обслуживания остановить задачу SerenBackground в Планировщике; перед запуском самостоятельных режимов убедиться, что фоновые дочерние процессы завершены, затем отключить config_background.json. Это не нужно для обычной работы и настройки.

В окне каждого фонового анализатора добавлена кнопка «Перезапустить фоновый анализатор». Команда подписана и адресуется только выбранному каналу; процесс штатно останавливает свои потоки и выходит с кодом 75, чтобы супервизор запустил его снова. Окно остаётся открытым и ждёт новый PID фонового процесса (до 45 секунд, затем сообщает о неподтверждённом перезапуске). Основной модуль и другой канал не перезапускаются. Кнопка доступна только в интерфейсе фонового режима, не в самостоятельном анализаторе или архивном отладчике. После установки этого изменения впервые перезагрузите рабочий ПК, чтобы фоновые процессы загрузили обработку команды.
