# Настройка тревог Seren

В конфигураторе доступны три степени опасности. У каждой — ракетный, бомбовый, дроновый и неопознанный вариант: всего 12 правил с независимыми звуковыми профилями. Ещё два профиля — отсутствие тревог (0) и отсутствие связи с онлайн-источниками (13).

## Выбор активной тревоги

1. Критическая опасность выше высокой, высокая выше низкой.
2. Итог включает все действующие типы угроз от API и независимых Telegram-каналов. При одинаковой степени приоритет ракета → бомба → дрон → неопознанная выбирает только один звуковой профиль; остальные типы остаются в итоговых индикаторах и битах ПЛК.
3. Несколько сообщений и источников хранятся одновременно. Угроза с меньшим приоритетом остаётся в анализе и становится активной после завершения более приоритетной.

Главное окно отдельно показывает базу API, вклад каждого Telegram-канала, итог, историю повышений и отмен. У каждого канала есть собственное состояние и чат ключевых сообщений с пуском, направлением, приближением и реакцией правил. Звуковая карточка показывает выбранное правило, время сообщения, источники, распознанное приближение, группу дрона, текст доказательства, срок действия и другие совпавшие правила. Отдельно отображаются подавление по расписанию и недоступные источники.

## Редактирование

Откройте конфигуратор → **12 правил тревог**. Внутри вкладок **Критическая**, **Высокая**, **Низкая** находятся четыре карточки: ракетная, бомбовая, дроновая, неопознанная.

- **Источники:** `API` — AlarmMap; `Telegram` — все каналы вкладки «Источники»; `@monitor1654` — только конкретный канал. Можно выбрать несколько через запятую. Канал должен присутствовать во вкладке «Источники».
- **Приближение Telegram:** пуск, над городом, над районом, направление на район. Можно включить несколько вариантов.
- **Группы дронов:** 1, 2, 3 из словаря; 0 означает неизвестную группу. Фильтр групп применяется только к Telegram. API не сообщает группу: его тревоги выбираются по типу и уровню независимо от выбранных групп.
- **API — типы и номера уровней:** явный фильтр по паре `type` + `level`. Несколько значений вводятся через запятую.
- **14 звуков:** количество гудков, длительность, пауза внутри серии, интервал между сериями. Каждый вариант имеет свой профиль. Длительность и пауза задаются с шагом 10 мс, интервал серий — с шагом 1000 мс, поскольку такие единицы использует текущая программа ПЛК. Значения должны помещаться в WORD (0..65535). Для тишины задайте количество гудков 0.

Значения внутри одного поля объединены по ИЛИ. Поля одного источника проверяются по И. Telegram использует тип угрозы + приближение + группу; API использует только тип события + уровень; Telegram-фильтры групп и приближения к нему не применяются. Один подходящий источник достаточен: правила не требуют подтверждения одновременно несколькими каналами.

Маркеры приближения редактируются на вкладке «Распознавание приближения». Для «над районом» и «направление на район» необходимо также совпадение со словарём районов. Для «над городом» — совпадение со словарём города или района. Само упоминание названия района не считается доказательством нахождения цели над ним. Тип цели определяется словарём дронов и маркерами ракет/КАБ; сообщение с несколькими типами создаёт несколько наблюдений.

## AlarmMap API

Номер уровня имеет смысл **внутри конкретного типа события**. Программа загружает название и пояснение из официального `/api/v1/emergencies/levels` и сопоставляет по `type` + `level`. В карточке API показаны все активные события, их уровень, территория и продолжительность. Кнопка «Справочник типов и уровней API» открывает полный полученный справочник.

Документация: https://alarmmap.online/developers/api/emergencies/levels

Если справочник недоступен, программа явно сообщает, что значение уровня не подтверждено; она не выдаёт номер уровня за географическую степень приближения. Сам API текущих событий не содержит положение цели или группу дрона. Настройки Telegram-приближения не применяются к API.

`air` — общая воздушная тревога; отдельного ракетного типа в полученном справочнике нет. Алгоритм от 2026-10-07:

1. При наличии уточнения КАБ (`kab-bombs`), дронов (`fight-drones`) или FPV (`fpv-drones`, также поддерживается `fpv`) общая запись `air` остаётся видимой, но не участвует в выборе тревоги. КАБ относится к бомбовой угрозе, дроны и FPV — к дроновой.
2. Без уточнения только `air` уровня 3 считается ракетной угрозой по правилу пользователя. Остальные уровни `air` классифицируются как дроновые; по умолчанию 2 соответствует высокой, 1 — низкой степени. Это эвристика приложения, а не подтверждение ракеты API.
3. Для явного типа используются его собственный номер уровня и фильтры правила. Для `air` в дроновых правилах есть отдельное поле уровней, поскольку `air/2` и `fight-drones/2` имеют разные значения. Неизвестные номера уровней не получают автоматически выдуманную степень опасности.
4. Ответ выбранной территории включает её родительские территории, поэтому уточнения учитываются во всём полученном снимке. Несколько уточняющих типов сравниваются по степени и приоритету типа. Ракетные сообщения Telegram остаются независимыми.

При обновлении прежние дроновые API-правила с `fight-drones` получают поддержку `air` и FPV; звуки, Telegram-условия, источники и прежние фильтры явных уровней сохраняются. Версия классификации сохраняется в `api_classification_version`. При необычном FPV-идентификаторе из справочника добавьте его в поле типов дронового правила: распознавание FPV поддерживает также название из справочника.

## Звук отсутствия связи

Во вкладке «Звуковые профили» доступен отдельный профиль 13 «Нет связи с онлайн-источниками». По умолчанию: 2 гудка по 200 мс, пауза 300 мс, пауза между сериями 5 с. Все параметры редактируются; количество 0 отключает этот звук.

Профиль используется при недоступности хотя бы одного включённого API/Telegram-источника, если нет действующей тревоги. Действующая тревога имеет приоритет, в том числе пока последний успешный снимок API ещё актуален. После восстановления связи выбирается обычный профиль. Отключённые источники не считаются неисправными. Тихий час и выключенный тумблер подавляют звук потери связи. Бит отсутствия связи сохраняется независимо от выбранного звука; интерфейс показывает потерю связи жёлтым цветом.

## Актуальность и передача

- Telegram использует время публикации, а не время получения. Сообщения без достоверного времени, старше TTL и из будущего игнорируются. Остаток TTL отсчитывается от публикации; повторный запуск не продлевает тревогу.
- Дедупликация — по ID и содержимому сообщения, а не по тексту: одинаковые новые сообщения не теряются. Отбой сбрасывает наблюдения своего источника и указанного типа/сектора, не снимая подтверждения других источников.
- Онлайн Telegram определяется успешным доступом к каждому каналу, даже если новых постов нет. Таймаут актуальности настраивается отдельно. При частичной потере источников выставляется бит отсутствия связи.
- Последний успешный снимок API используется до истечения настроенного срока актуальности. После этого он остаётся видимым как устаревший и не выбирает тревогу. Потеря связи не считается отбоем.
- Heartbeat вычисляется в Modbus-потоке. Медленный API и отрисовка окна не задерживают его. Если сам анализатор перестал обновлять состояние более чем на 3 секунды, отправка heartbeat прекращается, чтобы ПЛК обнаружил остановку по своему watchdog.
- Вместо накопления старых команд передаётся последнее вычисленное состояние. Профиль `%MW2..%MW6` и `%MW0` записываются двумя запросами, без изменения принадлежащего ПЛК `%MW1`. Это не атомарная транзакция; подтверждение означает успешные ответы на оба запроса, а не проверку физического реле.
- Журнал разделяет расчёт тревоги и подтверждённую запись команды в ПЛК.
- Тихий час **23:40–02:00** сохранён: анализ и объяснение продолжаются, команда тревоги подавляется и звуковые параметры обнуляются. Действующая логика ПЛК и состояние реле требуют отдельной аппаратной проверки.

Прежние звуковые параметры переносятся в новую схему при загрузке старой конфигурации. Новые правила и все настройки сохраняются атомарно в `config_threats.json`. Отмена и ошибки ввода не меняют действующую конфигурацию.

## Эвристика и окончание угроз

Во вкладке «Эвристика / окончание» доступны словари начала атаки и носителей, контекст движения, признаки неопределённости/продолжения атаки и редактируемые условия окончания. Для каждого условия задаются типы угроз, каналы, фразы, исключения, действие (снять/выдержка/без снятия), окно контекста и необходимость подтверждённого сообщения. «Региональный отбой» разрешает снять все подходящие наблюдения своего канала в указанной зоне; обычное падение требует однозначной цели.

В приближении добавлено отдельное «Направление на город»: направление не выдаётся за нахождение над городом. Короткие сообщения могут наследовать тип только из свежего однозначного контекста своего канала. При нескольких целях продвижение и отдельный прилёт не снимают все угрозы. Верхняя лампа показывает физический тумблер оповещения из `%MW1`; при отсутствии связи состояние обозначается как неизвестное.

Исследование и порядок тестирования запаса 90–120 с: [TELEGRAM_ANALYSIS.md](TELEGRAM_ANALYSIS.md).

Для цели ранней эвакуации рабочие критические **ракетные и бомбовые** правила теперь включают «Направление на город» и «Над городом», а также прежние районные признаки. Пуск КАБ не включён в критическое правило; этот вариант оставлен отдельной экспериментальной конфигурацией. При совпадении критического и высокого правила выбирается критическое. Начальные API-уровни КАБ/дронов уточнены по справочнику: 2 — критическое соответствие, 1 — высокое; низкое остаётся Telegram-условием. Значения пользователь может изменить.

В рабочей конфигурации по выбору пользователя включён низкий дроновый вариант только для API (источник `alarmmap`); ранее отключённые низкие Telegram-оповещения сохранены. В высоких правилах дронов и КАБ добавлен API-уровень 1; прежние уровни и звуковые параметры сохранены.

## База API и независимые каналы

Итоговый уровень равен максимуму базы API и действующих Telegram-дополнений, включая городскую/районную степень. Типы объединяются. Telegram не снижает действующую базу API и может создать тревогу без неё. Отбой одного канала снимает только его подходящие наблюдения; подтверждения других каналов сохраняются. При TTL или окончании выдержки отдельно показываются источник и причина снятия. Движение вне города/от города распознаётся в контексте своего канала; при уходе цели применяется существующее настроенное действие keep/replace/shorten и выдержка, а не безусловное снятие всей тревоги.

Архивное тестирование использует этот же анализатор; см. ARCHIVE_TESTING.md.


Исправлено сохранение тревоги при неизвестном новом положении цели: движение без распознанного приближения или без совпадения включённого правила не сокращает и не удаляет прежнее наблюдение. Исходный TTL не продлевается. Связь с прежним наблюдением сохраняется через цепочку уточнений; подтверждённый уход вне/от города, распознанная новая зона и явная отмена работают по настроенным правилам. В восстановленном архиве monitor1654 за 5 октября КАБ сохраняет уровень 1 до распознанной угрозы городу в 14:41:25, повышающей уровень до 4; падения до 0 в 14:41:10 нет. После исправления цитат текстовая хронология отличается от прежних отчётов. Общая проверка: 95 тестов.
