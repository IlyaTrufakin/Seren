# Передача работы Seren — 2026-10-07

## Что нужно продолжить

Последнее требование пользователя: API задаёт базовый уровень и тип тревоги в городе. Каждый Telegram-канал ведёт независимые наблюдения от пуска, типа цели и движения до приближения и отмены. Итог — максимальный действующий уровень и объединение всех действующих типов. Telegram может установить тревогу без базы API; отмена одного канала не отменяет базу API и подтверждения других каналов. На экране нужны база, состояние и чат ключевых сообщений каждого канала, итог, источник повышения и причины отмены/TTL. Работу должно быть возможно проверить на архивных сообщениях.

## Реализовано в рабочем приложении

- API: уточняющие КАБ/дроны/FPV имеют приоритет над общей записью air. Без уточнения air/3 считается ракетной угрозой, air/1–2 — дроновой. Фильтры групп дронов применяются только к Telegram.
- 12 правил (3 степени × ракетная, бомбовая, дроновая, неопознанная), 14 звуков: 0 — обычный режим, 1..12 — тревоги, 13 — отсутствие связи хотя бы с одним включённым онлайн-источником. Действующая тревога имеет приоритет над звуком отсутствия связи.
- API-фильтры обновлены с сохранением звуков и поведения Telegram; низкий дроновый вариант включён только для API. В high_drone/high_kab добавлен API-уровень 1. Пользователь после этого редактировал конфигурацию: текущий config_threats.json считать источником правды.
- Панели битов MW0/MW1 удалены. Обработка ПЛК-тумблера, сброса и Modbus осталась.
- Карточка API сокращена до трёх полей: общая тревога, тип, уровень этого типа.
- Добавлена кнопка «Архив Telegram», запускающая отдельный тестовый процесс.

## Новая схема: подключена к рабочему приложению

- src/threat_composition.py — чистый расчёт базы, независимых вкладов каналов, всех типов и истории изменений.
- src/archive_replay.py — автономный исторический движок: время публикации, TTL/выдержки, расписание, движение, самостоятельные контексты каналов, необязательная тестовая база API. Онлайн-читатели и API запрещены; транспорта ПЛК нет.
- src/archive_viewer.py — отдельное окно: состояние/чат каждого канала, шаг, воспроизведение, переход, +60 с, правила теста без перезаписи рабочих настроек, экспорт CSV.
- run_archive.bat — запуск окна. Можно запускать .venv/Scripts/python.exe -m src.archive_viewer с путями к архивам.
- ARCHIVE_TESTING.md — инструкция и ограничения (UTC+03 для предоставленного корпуса сентября–октября 2026; тестовая постоянная база API не является историей API).
- src/threat_models.py содержит новые поля диагностики и словарь outside/away_city. Направления outside/away_city подключены к общему рабочему и архивному парсеру; действуют существующие настройки движения и выдержки.
- ThreatConfigDialog поддерживает persist=False для временных архивных настроек.

ВАЖНО: src/threat_evaluator.py подключён к ThreatComposition. Рабочая программа выбирает максимальный уровень и объединяет все действующие типы. Для звука остаётся одно приоритетное правило. В главном окне подключены независимые состояния и чаты каналов через src/channel_panels.py. Архив использует этот же анализатор, отдельных правил/парсера в OfflineEvaluator больше нет.

## Проверки

Все 80 тестов прошли: .venv/Scripts/python.exe -m unittest discover -s tests -v.

Архивный прогон двух локальных JSONL-файлов: 10 951 сообщение, два канала. Сеть была явно запрещена через mock urllib.request.urlopen. Проверен возврат в нулевую тревогу после истечения всех наблюдений. CSV: logs/archive_replay_report.csv. Прежние численные результаты относились к первоначальному архивному прототипу. CSV обновляется прогоном общего анализатора; актуальные счётчики в logs/archive_replay_summary.json. Это состояния/тики, не количество отдельных тревожных эпизодов.

Новые тесты: tests/test_archive_replay.py, tests/test_threat_composition.py и tests/test_live_composition.py. Предыдущие: tests/test_api_and_source_sound.py, tests/test_alarm_system.py, tests/test_plc_sound.py.
