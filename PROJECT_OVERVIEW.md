# Seren — архитектура и эксплуатация

## Назначение

Windows-приложение Python/Tkinter получает оперативные сообщения из Telegram и текущие события AlarmMap API, применяет девять пользовательских правил тревоги и передаёт команды оповещения в Schneider Electric Modicon M221 (TM221CE16R) по Modbus TCP.

Актуальная инструкция по настройке: [ALARM_RULES.md](ALARM_RULES.md).

## Девять тревог и десять звуков

| Степень | Ракетная | Бомбовая | Дроновая |
|---|---|---|---|
| Критическая | Профиль 1 | Профиль 2 | Профиль 3 |
| Высокая | Профиль 4 | Профиль 5 | Профиль 6 |
| Низкая | Профиль 7 | Профиль 8 | Профиль 9 |

Профиль 0 — отсутствие тревог. Степень важнее типа; внутри степени приоритет ракета → бомба → дрон. Источники, приближение, группы дронов и соответствия type/level API настраиваются для каждого правила независимо. Прежние параметры звуков переносятся при миграции, номера профилей соответствуют новой таблице.

## Архитектура

- `main.py` — запуск главного окна.
- `src/app.py` — интерфейс, просмотр причины тревоги, подтверждение передачи, отображение `%MW0`/`%MW1`. Все операции Tk выполняются в GUI-потоке; состояния от анализатора передаются как отдельные снимки.
- `src/threat_models.py` — конфигурация, девять правил, звуковые профили, наблюдаемое состояние, проверка входных данных и атомарное сохранение.
- `src/threat_config_dialog.py` — редактор источников, районов, девяти правил, десяти звуков, словаря дронов и тихого часа. Работает с копией настроек до успешного сохранения.
- `src/threat_evaluator.py` — наблюдения нескольких угроз и источников, TTL по времени публикации, выбор активного правила, причины и расшифровка API. Опрос API выполняется отдельно от цикла анализа.
- `src/telegram_reader.py` — публичные страницы Telegram или Telethon; идентификаторы сообщений и состояние связи по каждому каналу.
- `src/modbus_worker.py` — соединение и опрос ПЛК, последнее состояние управления, heartbeat независимо от GUI/API, подтверждения записей.
- `src/audit_logger.py` — ежедневный журнал исходных данных, расчёта и отдельно подтверждённых команд.
- `src/ui_theme.py` — оформление и битовые индикаторы.

Настройки: `config.json` (Modbus), `config_threats.json` (анализ и звук). API-ключ: `API/alarmmap.online.txt`. Ключи, сессии, виртуальное окружение и журналы исключены через `.gitignore`.

## Регистры ПЛК

| Регистр | Направление | Назначение |
|---|---|---|
| `%MW0` | ПК → ПЛК | Уровень, выбранный тип угрозы, отсутствие связи, тишина, heartbeat |
| `%MW1` | ПЛК → ПК | RUN (бит 15), кнопка сброса (бит 1), тумблер (бит 2) |
| `%MW2` | ПК → ПЛК | Код активного звукового профиля 0..9 |
| `%MW3` | ПК → ПЛК | Число гудков |
| `%MW4` | ПК → ПЛК | Длительность гудка, мс |
| `%MW5` | ПК → ПЛК | Пауза внутри серии, мс |
| `%MW6` | ПК → ПЛК | Интервал между сериями, мс |

Существующая битовая схема сохранена: бит 0 — отсутствие тревог; 1 — низкая; 2/3 — высокая для города/района; 4/5 — критическая для города/района; 6/7/8 — выбранная ракетная/бомбовая/дроновая; 9 — недоступен хотя бы один включённый источник; 10 — тихий час; 15 — heartbeat. При API район физически не выводится из номера уровня, поэтому используются городские биты степени.

`%MW1` никогда не перезаписывается при отправке автоматической команды. `%MW2..%MW6` и `%MW0` отправляются двумя запросами. Подтверждение обоих запросов записывается отдельно от расчёта; это не доказательство состояния выходного реле.

## Аппаратная часть

IP по текущей конфигурации: `192.168.0.221`, порт `502`, Unit ID `255`, период опроса `200` мс. ПК и контроллер должны быть в одной подсети.

Проекты `Seren_Alarm.smbp` и `Seren_Alarm_Fixed.smbp` содержат одинаковые InstructionLine (16 цепей). `Seren1.smbp` — отдельный проект с 8 цепями. Исполняющая программа в реальном ПЛК не определялась в ходе изменения приложения.

Текущий PLC-watchdog рассчитан на 12 секунд. В штатном режиме `LDN %M0` копирует параметры ПК в активные уставки; при потере связи `LD %M0` включает резервные параметры. Временные уставки ПЛК имеют шаг 100 мс для импульса/паузы и 1 с для интервала серий. Поэтому конфигуратор проверяет эти кратности.

Программа сохраняет существующую команду тихого часа 23:40–02:00: звук и тревожные биты подавляются, анализ отображается. Поведение реальных выходов при нулевых уставках должно проверяться на оборудовании; приложение не сообщает, что физическое реле выключено, без его чтения.

## Запуск и проверка

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

Или используйте `run.bat`. `run_watchdog.bat` перезапускает завершившийся процесс, но не диагностирует зависание приложения.

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Автоматические проверки покрывают девять тревог, приоритеты, актуальность сообщений, источники, группы дронов, расшифровку API, независимость анализа от медленного API, тихий час, сохранение/миграцию конфигурации, отмену/ошибки конфигуратора и обмен с локальным TCP-имитатором ПЛК. Реальный ПЛК, реальные API и сирена при этих проверках не используются.
