## 1. О проекте (Project Overview)

- **Название проекта**: `Seren` / TM221 Modbus Gateway
- **Целевая платформа**: Windows 10 / Windows 11
- **Стек технологий**:
  - Python 3.10+ (разработано и протестировано на Python 3.14.6)
  - Графический интерфейс: `Tkinter` + `ttk` (современная темная промышленная тема, стилизация под HMI-панель)
  - Протокол связи: `pymodbus` (v3.15.0) — Modbus TCP клиент
  - Хранение настроек: `json` (`config.json`)
- **Основная задача**:
  Обеспечение стабильного двустороннего циклического обмена данными между ПК под управлением Windows и программируемым логическим контроллером (ПЛК) по протоколу Modbus TCP:
  1. **Передача слова данных (WORD)** с ПК в ПЛК в регистр `%MW0`.
  2. **Прием слова данных (WORD)** из ПЛК в ПК из регистра `%MW1`.
  3. Полная сетевая настройка (IP, порт, Unit ID, таймауты, период опроса).
  4. Визуализация в форматах DEC (Unsigned / Signed), HEX, BIN и побитовая интерактивная матрица (биты 0..15).

## 2. Аппаратная часть и сетевая топология (Hardware & Network)

- **Модель ПЛК**: Schneider Electric Modicon M221 (маркировка: `TM221CE16R`).
- **Среда разработки ПЛК**: EcoStruxure Machine Expert - Basic (ранее SoMachine Basic).
- **Сетевой интерфейс ПЛК**:
  - **IP-адрес контроллера**: `192.168.0.221`
  - **Маска подсети**: `255.255.255.0`
  - **Шлюз**: `192.168.0.1` (или прямой кабель Ethernet к сетевой карте ПК)
  - **Порт Modbus TCP**: `502`
  - **Unit ID / Slave ID**: `255` (контроллер также отвечает на Unit ID `1`).
- **Фактический отклик сети**:
  - Пинг и сокет отвечают со средней задержкой ~1.0–1.8 мс.

## 3. Адресация памяти и протокол Modbus (Addressing & Protocol Mapping)

В контроллерах Schneider Electric M221 память слов `%MW` жестко сопоставлена с таблицей Holding Registers протокола Modbus:

| Переменная в ПЛК | Modbus Register (0-based) | Modbus Register (1-based / PLC) | Направление обмена | Описание |
|---|---|---|---|---|
| **%MW0** | `0` | `40001` | **ПК ➔ ПЛК (Запись)** | Слово управления / данных, передаваемое с компьютера в ПЛК. Функции Modbus: FC06 (Write Single) или FC16 (Write Multiple). |
| **%MW1** | `1` | `40002` | **ПЛК ➔ ПК (Чтение)** | Слово состояния / данных, формируемое в ПЛК и считываемое компьютером. Функция Modbus: FC03 (Read Holding Registers). |

> **Важно**: В программе адреса регистров конфигурируемы (пользователь может при необходимости сменить `%MW0` и `%MW1` на любые другие адреса `%MW` прямо в интерфейсе).

## 4. Архитектура программного обеспечения (Software Architecture)

Архитектура построена по принципу асинхронного неблокирующего взаимодействия потоков (Threaded Worker Pattern), что гарантирует плавность интерфейса Windows без зависаний:

```
[Пользователь / GUI (Tkinter)]  <==== Queue (event_queue) ==== [Фоновый поток (ModbusWorker)]
       |                                                                  |
       |--- Запись в очередь (queue_write / set_cyclic_write) ----------->|
       |                                                                  |
  [config.json] <--------------------------------------------- [Socket / Modbus TCP]
                                                                          |
                                                                  [ПЛК M221: 192.168.0.221]
```

### Структура модулей:
1. **`main.py`**:
   - Точка входа в программу. Инициализирует и запускает `ModbusApp`.
2. **`run.bat`**:
   - Скрипт быстрого запуска для Windows. Проверяет наличие виртуального окружения `.venv`, при его отсутствии автоматически создает его, устанавливает `requirements.txt` и запускает приложение без лишних консольных окон.
3. **`config.json`**:
   - Хранилище настроек приложения (сохраняется автоматически при изменении настроек).
4. **`src/config.py` (`AppConfig`)**:
   - Датакласс настроек: `host`, `port`, `unit_id`, `timeout`, `poll_interval_ms`, `auto_reconnect`, `write_reg_address`, `read_reg_address`, `cyclic_write`, `write_on_change`, `last_write_value`.
5. **`src/modbus_worker.py` (`ModbusWorker`)**:
   - Работает в отдельном потоке (`threading.Thread`).
   - Управляет жизненным циклом соединения (`ModbusTcpClient`).
   - Выполняет циклический опрос `read_holding_registers`.
   - Обрабатывает очередь разовых/ручных записей `write_register` и режим циклической непрерывной записи.
   - Измеряет задержку RTT (время отклика в мс).
   - При ошибке или обрыве связи автоматически выполняет плавное переподключение (при включенном `auto_reconnect`).
   - Отправляет события в GUI через `queue.Queue`:
     - `status`: состояние соединения (`connected`, `connecting`, `disconnected`, `error`).
     - `read_ok`: успешное чтение с адресом, значением и RTT.
     - `write_ok`: успешная запись с адресом, значением и RTT.
     - `error`: детальное описание ошибки.
     - `stats`: статистика запросов (всего, ошибки, средняя задержка).
6. **`src/ui_theme.py`**:
   - Определение цветовой схемы HMI (Dark Industrial Slate).
   - Класс `LedIndicator`: светодиодный индикатор состояния на Canvas.
   - Класс `WordBitsWidget`: 16-битная панель (биты 15..0) с разбивкой по тетрадам/байтам. Поддерживает интерактивный режим (клик по кнопке бита переключает его состояние и мгновенно пересчитывает число в WORD) и режим индикатора (светодиодные лампы состояния для чтения).
7. **`src/app.py` (`ModbusApp`)**:
   - Основное окно приложения на базе `tk.Tk`.
   - Верхняя панель: заголовок, LED-статус, счетчик сетевой задержки.
   - Блок сетевой конфигурации: редактирование IP, порта, Unit ID, периода опроса; кнопка быстрого пинга сокета.
   - Блок передачи в ПЛК: ввод DEC/HEX, интерактивные биты 0..15, кнопки `0x0000`, `0xFFFF`, `+1`, `-1`, выбор режима отправки (вручную, по изменению, циклически).
   - Блок приема из ПЛК: крупное табло DEC/Signed/HEX/BIN, 16 светодиодов бит, метка времени с точностью до мс.
   - Журнал обмена: цветной лог с временными метками и опцией автопрокрутки.

## 5. Как развернуть и запустить проект на новом компьютере (Setup & Run)

### Шаг 1: Клонирование репозитория
```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd Seren
```

### Шаг 2: Запуск (автоматический)
Просто запустите файл:
```bat
run.bat
```
*(Файл `run.bat` сам создаст `.venv`, установит `pymodbus` из `requirements.txt` и откроет GUI).*

### Шаг 3: Запуск (вручную через терминал)
```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

   - Автоматическая запись истории принятых и переданных значений в файл с отметками времени.
4. **Сборка в единый исполняемый файл `.exe` (PyInstaller)**:
   - Создание полностью автономного дистрибутива, не требующего установленного Python на целевом ПК:
     ```powershell
     .venv\Scripts\pip install pyinstaller
     .venv\Scripts\pyinstaller --noconsole --onefile main.py -n "TM221_Modbus_Gateway"
     ```
5. **Расширение диапазона регистров**:
   - Поддержка чтения/записи блоков регистров (например, `%MW0..%MW9`).
